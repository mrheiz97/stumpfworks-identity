# Identity v1.13.1

This release publishes the tested development scope through the protected
PR/main CI/signed tag/source-release workflow. Publication does not deploy
software, change the production catalog or create an update job. The first
scheduled WYSE01 job remains a separate production maintenance operation.

Changes since v1.13.0: preserve safe shared client-directory permissions in the
VNC password helper; reject unsafe/symlink targets; explicitly disable both VNC
IPv6 listeners; root-controlled Stable-catalog deployment profile and real Unix
permission regression contracts; tested worker/timer operational documentation.
No new database migration, API, authentication mode, Framework dependency or
automatic client deployment. Embedded application version is 1.13.1.

The first scheduled candidate deliberately packages only the newly built
1.13.1 status reporter. The helper/VNC fixes are already separately deployed on
WYSE01 and are not in this signed ZIP. Worker and updater remain1.13.0; no
greeter/PAM/units/device-tool mutation. The status-only update exercises signed
scheduled delivery with a genuine new versioned build, not renamed old bytes.

Build from the clean exact release commit and record SHA256 and VCS/toolchain
metadata. The earlier development candidate is retained as historical evidence;
its hashes are not release approval hashes. Rebuild and sign a separate package
from the exact release commit and repeat actual-package tests. Never silently
substitute new bytes under an existing approval. GitHub publishes the source
release; the signed WYSE01 ZIP/local catalog proposal is prepared separately and
is not automatically uploaded to any production system or scheduled.

Full local PostgreSQL17/import/restore/TLS/OpenSSL suite and vet, Linux CI with
race detector/PostgreSQL16 and the actual signed-package rehearsal against the
installed1.13.0 worker code are required evidence. The rehearsal uses synthetic
clients, local stores and service stubs; it does not claim hardware maintenance.

Rollback for the scoped job restores the exact1.13.0 status reporter plus its
original mode, retaining validated job journal/result/audit evidence. A DB restore
is not the normal component rollback. Do not downgrade worker/updater or remove
their installed-version floor to force another attempt. MOBILE01 is excluded.
