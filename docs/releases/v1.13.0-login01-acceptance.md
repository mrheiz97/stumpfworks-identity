## Retained recovery boundary

Preserve the stopped schema-6 recovery set and current backups through normal
retention. New application writes resumed after restart. Restoring the
pre-deployment dump now would discard subsequent writes and requires an
explicit data-loss/reconciliation decision; do not perform a silent database
downgrade or delete the migration ledger/table. Keep the failed/current state
before selecting any restore path. The [maintenance plan](v1.13.0-login01-rollout.md)
defines the recovery branches. Off-host backup confirmation remains a separate
operational follow-up; same-host rollback does not protect against host/storage
loss. No client rollout is included or implicitly authorized.
