# Identity v1.13.0

This release publishes the tested development scope. It does not install
software, modify production configuration or activate client update polling.

## Included changes

- Opt-in scheduled managed-client updates: protected administration, an approved
  signed stable catalog, bounded job lifecycle, cancellation and transactional
  audit on SQLite and PostgreSQL. The separate mTLS worker reuses signed
  installation/recovery, a shared OS lock and a durable crash/retry journal.
- Read-only client certificate overview and protected minimal JSON endpoint:
  authentication mode, token fallback policy, certificate status, UTC expiry
  and pending activation, with roles and secret-free output.
- Framework v1.2.0 peer/issued-certificate verifiers with Identity URI/client-ID,
  algorithm, CA and lifecycle policy retained locally. Go 1.26.10 is required.
  Frozen test-only baseline comparisons and explicit defensive differences
  are documented in the certificate migration record.

## Release checks

The release uses the protected development-to-main pull request, required CI,
main CI, an annotated immutable `v1.13.0` tag and a public GitHub source release.
The embedded version must report `1.13.0` before publication. Build candidates
must come from the exact release commit with `vcs.modified=false`; record their
SHA-256 hashes and dependency/toolchain metadata locally. No client-update
catalog entry or signed deployment bundle is published implicitly by this
GitHub source release. Such artifacts require the separate existing signing
and catalog approval process.

Local verification includes the complete suite and vet with disposable
PostgreSQL 17, import/reconciliation/custom-dump restore, TLS/OpenSSL, module
verification and portable old/new certificate contracts. Linux CI adds race
detection, PostgreSQL 16, Prometheus, Python, shell and whitespace checks.
Hardware login and production acceptance are not claimed by these checks.

## Deployment and rollback boundary

The former stable release is `v1.12.2`; preserve its immutable tag. A local
source archive and Go-1.26.10 Linux binary recovery set can be prepared from
that tag without production data. This proves a rebuildable software baseline,
not a backup of a running installation. The separately checked certificate-only
rollback to development `4f4fc25` does not undo the entire v1.13.0 scope.

Migration **7** adds scheduled-update jobs. PostgreSQL migration requires the
existing migration account; runtime has no DDL privileges. SQLite applies its
equivalent schema on opening. A future deployment requires a fresh read-only
preflight and a stopped, consistent, hash-verified binary/configuration/database
backup. An old binary alone is insufficient for complete rollback after schema
or job writes. There is no destructive automated down-migration.

Before downgrading an activated worker, stop/disable its timer, let the oneshot
finish, reconcile dispatched jobs and finish pending recovery. Preserve job
journals, rollback artifacts and audit history. Restore the verified matching
binary/unit/configuration set and consistent database snapshot under the
separately authorized maintenance plan; account explicitly for writes after
that snapshot. Never enable the new worker alongside an old unlocked updater.

Existing client authentication modes, CA, certificate bundles, tokens and
listener activation remain untouched by publication. Any later server/client
rollout requires its own approval and acceptance. No production action is
authorized by this release document.
